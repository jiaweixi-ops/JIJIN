# V1.3 Phase 3 — 可信外部研究采集

## 目标

Phase 3 在 `Research Inbox` 前增加一个受控采集层，用来自动读取**显式注册**的 RSS/Atom/JSON Feed，并把规范化材料交给 Phase 2 的持久化研究流水线。

这不是“开放网络爬虫”。调度器不能接收临时 URL，也不会根据模型输出自行决定去哪里抓取。只有 system/ADMIN 预先登记的数据源才会被访问。

```text
Registered Collection Source
    -> Safe HTTP Fetch
    -> RSS / Atom / JSON Feed Normalize
    -> durable ResearchCollectedDocument
    -> ResearchInbox (idempotent)
    -> Kimi
    -> Qwen + Evidence
    -> DeepSeek CIO
    -> SUGGESTED
    -> Python Risk
    -> PENDING_CONFIRM
```

## 数据模型

### `research_collection_source`

一条来源绑定：

- `account_id`
- `fund_id`
- `name`
- `adapter`: `rss` 或 `json_feed`
- `feed_url`
- `topic_prefix`
- `enabled`
- ETag / Last-Modified
- 最近检查、最近成功、最近错误

唯一边界：

```text
(account_id, fund_id, feed_url)
```

同一个 feed 可以在不同模拟账户/基金映射下分别登记，但同一目标不能重复登记。

### `research_collection_run`

每次抓取都有独立运行记录，包含：

- trigger (`manual` / `scheduler`)
- status
- HTTP status
- fetched / ingested / duplicate / rejected 数量
- error
- started_at / finished_at

失败不会擦掉历史运行记录。

### `research_collected_document`

标准化后的外部材料会保存：

- `external_id`
- `fingerprint`
- `content_sha256`
- title / canonical_url
- published_at / observed_at
- normalized content
- 对应 `research_item_id`

`fingerprint = sha256(external_id + content_sha256)`。同一外部 ID 的内容若发生真实变化，会形成新 fingerprint；完全相同的材料不会重复进入 Research Inbox。

## 网络安全边界

默认只允许 HTTPS：

```text
RESEARCH_COLLECTION_ALLOW_HTTP=false
```

注册和抓取会拒绝：

- 非 HTTP(S) scheme
- URL 中嵌入 username/password
- localhost / `*.localhost`
- literal private / loopback / link-local / reserved IP

真正发请求前还会解析 DNS，若任何返回地址不是 global/public 地址则拒绝。每次重定向都会重新执行 URL 与 DNS 校验，避免通过重定向直接跳向内网。

注意：应用层 DNS 预检查无法从理论上完全消除 DNS rebinding 的 TOCTOU 风险。生产部署仍应在网络层给容器配置 egress policy，只允许所需公网出口，并禁止访问云 metadata、RFC1918、宿主机和内部控制面。

## HTTP 限制

默认：

```text
RESEARCH_COLLECTION_TIMEOUT_SECONDS=15
RESEARCH_COLLECTION_MAX_BYTES=2000000
RESEARCH_COLLECTION_MAX_REDIRECTS=3
RESEARCH_COLLECTION_MAX_ITEMS_PER_SOURCE=20
RESEARCH_COLLECTION_BATCH_SIZE=20
```

只接受下列 feed 类型：

- `application/rss+xml`
- `application/atom+xml`
- `application/feed+json`
- `application/json`
- `application/xml`
- `text/xml`

不把任意 HTML 页面当作 feed 抓取，也不在采集器内执行 JavaScript。

ETag 与 Last-Modified 会被持久化，后续请求发送 `If-None-Match` / `If-Modified-Since`。HTTP 304 记为成功运行，但不会产生新 Inbox 项。

## API

所有接口都要求内部认证。

只读：

```text
GET /research/collection/sources
GET /research/collection/runs
GET /research/collection/documents
GET /research/collection/documents/{document_id}
```

仅 system / ADMIN：

```text
POST  /research/collection/sources
PATCH /research/collection/sources/{source_id}
POST  /research/collection/sources/{source_id}/collect
```

人工注册示例：

```json
{
  "account_id": "<simulation-account-id>",
  "fund_id": "<fund-id>",
  "name": "fund-company-official-feed",
  "adapter": "rss",
  "feed_url": "https://example.org/research/feed.xml",
  "topic_prefix": "基金公司官方研究",
  "enabled": true
}
```

## 调度

默认 `Asia/Shanghai`：

```text
08:15  research_collection_morning
08:45  morning_brief
12:45  research_collection_predecision
13:15  research_pipeline
13:30  early_cutoff
14:00  decision_window
```

采集与 AI 研究是两个独立阶段。采集失败不会直接改变订单；研究流水线仍只处理成功进入 `Research Inbox` 的持久化材料。

## 与 DataQuality 的区别

`DataSource` / `DataQualityGate` 负责基金交易规则、公告获取健康度、费率版本、NAV 等“能否研究/结算”的可信状态。

`ResearchCollectionSource` 负责“从哪里自动收研究材料”。两者不要合并成一个表：一个研究 feed 能正常拉取，不等于基金交易规则就是 GREEN；反之亦然。

## 故障处理

来源失败：

- `ResearchCollectionRun.status=FAILED`
- `ResearchCollectionSource.last_error` 保留失败原因
- 其他来源继续执行
- 不生成伪造 Inbox 材料

解析条目异常：

- 单条空内容、未来发布时间、超长内容计入 `rejected_count`
- 同 fingerprint 计入 `duplicate_count`
- 不通过“截断后照样交易”的方式掩盖材料质量问题

## 非目标

Phase 3 不包含：

- 通用网页爬虫
- 搜索引擎全网发现
- JavaScript 浏览器抓取
- 模型自行新增来源
- 自动批准订单
- 自动提交模拟交易
- 实盘交易

如果以后增加网页抓取或搜索连接器，应作为独立 adapter，并继续经过显式来源策略、网络 egress 限制、内容审计和 Research Inbox 幂等边界。
