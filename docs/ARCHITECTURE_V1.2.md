# AI 场外基金公司 V1.2 — 开发基线

## 1. 产品边界

V1.2 定位为**个人研究 + 前瞻模拟盘工具**，默认 `SimulationBroker`，不连接真钱账户、不自动提交真实交易。所有输出使用“研究观点 / 候选方案 / 模拟执行”措辞，不承诺收益。若未来公开收费、自动实盘、代客操作或面向他人提供个性化建议，应重新进行合规、资质、数据授权和安全评估。

用户需要完成风险测评、适当性匹配和免责声明确认。风险测评与免责声明均版本化、有有效期、有审计记录。

## 2. AI 分工

- **Kimi：研究院** — 新闻、政策、公告、基金经理、长文档与反方证据；只生成可核验事实。
- **Qwen：数据研究中心** — 结构化、去重、冲突标记、资料抽取；不能改账本、费率或硬风控。
- **DeepSeek：CIO** — 读取 Kimi/Qwen/Python 输出形成模拟候选方案；必须引用 `evidence_id`。证据不足、数据 RED 或 CIO 不可用时默认 WAIT，不允许用其他模型替代 CIO。
- **Python：确定性引擎** — 账本、费用、份额、仓位、净值、风险、截止时间、对账、模拟确认。

AI 输出使用 Schema v1.2，模型版本、提示词版本、Token、耗时、错误进入 `model_call_log`。

## 3. 每日节奏

- 08:45：飞书盘前简报。只用已确认净值计算昨日与累计盈亏；附今日特殊截止时间和数据新鲜度。
- 13:30：对提前截止、QDII/港基/特殊销售平台进行预提醒。
- 14:00：发送模拟交易候选卡。每只基金显示代码、名称、板块、金额/份额、订单版本、数据时间戳、逐基金截止时间与有效期、理由、风控状态。
- 晚间：正式净值到达后确认模拟订单并更新账本。
- 月末最后一个交易日：已确认数据先出月报；QDII/FOF 未确认项目列为 pending，后续 `revision+1` 补记。

## 4. 交易截止时间

交易窗口由 `销售平台 × 基金 × 支付渠道 × 交易日历` 决定，而不是统一 15:00。`Fund.cut_off_time` 是基础字段，生产数据源应覆盖平台例外。订单有效期默认不晚于 `cut_off_time - 10min`；修改订单**不会延长截止时间**，新版本必须重新风控。

超时未确认：自动 `EXPIRED`，不自动顺延；下一交易日重新拉数据并生成新订单。临近提前截止的基金由 13:30 预提醒。

## 5. 费用、份额类别和持有批次

短周期候选可优先评估 C 类 / 联接 C，但必须把销售服务费、申购费、赎回费、转换费一并纳入。费率按版本记录，变化未确认时 DataQuality=RED。

持仓按 `HoldingLot` 批次保存。默认 FIFO 处理赎回费和份额占用；实际销售平台若使用其他批次规则，应以平台确认单为准并进入对账。持有不足基金规则要求天数时，普通模拟卖出为硬阻断。`emergency_exit=true` 是显式硬风控例外流程：要求二次确认、展示惩罚性费用、记录审批人与审计，不代表一般软风控可以覆盖硬风控。

## 6. 在途资产与正式账本

账户区分：`available_cash` 可用现金、`frozen_cash` 已下单冻结、`in_transit_cash` 赎回确认后待到账、已确认基金市值、在途份额/订单。在途资金不得用于新模拟买入。盘中估值只用于研究展示，不进入正式账本。

申购：预计份额 → 正式净值 → 实际份额。赎回：预计金额 → 正式净值/费用 → 实际到账。

## 7. 订单状态机

主链：`SUGGESTED → PENDING_RISK → PENDING_CONFIRM → APPROVED → SUBMITTED → IN_TRANSIT → CONFIRMED`。

旁路：`RISK_REJECTED / MODIFIED / PARTIALLY_CONFIRMED / EXECUTION_FAILED / EXPIRED / CANCELLED / MANUAL_RECONCILED`。

关键规则：

1. 每单唯一 `order_id + version + idempotency_key`。
2. 用户修改后 `version+1`，旧卡片点击返回“版本已过期，请使用最新卡片”。
3. 修改后回到重新风控流程，不继承旧风控结论。
4. 飞书重复回调必须幂等；重复 `idempotency_key` 返回原订单。
5. `CONVERT` 建两条 `order_leg`：OUT / IN，分别跟踪确认。
6. 部分确认进入 `PARTIALLY_CONFIRMED`；巨额赎回/暂停赎回保留未确认量，直到后续确认或人工回填。
7. 终态不允许普通事件反向修改；人工修复必须走 `MANUAL_RECONCILED` 与审计。

## 8. 数据质量闸门

以下为可配置的**工程默认值，不是监管规则**：

- GREEN：关键字段齐全、无关键冲突、净值时间小于 36h、费率版本已确认、申赎状态已知。
- YELLOW：净值 36–72h、净值未确认、公告抓取异常等非关键缺口。允许研究，但必须显示警告。
- RED：净值超过 72h、缺少净值时间戳、费率版本缺失/变化未确认、申赎/限购状态未知、关键源冲突或关键字段缺失。阻断新订单。

数据源保存优先级和 SLA。生产环境应让基金公司、销售平台和官方公告拥有更高优先级。新闻去重以来源 URL、标题归一化和发布时间为基础，研究层显式保留来源与可信度。

## 9. 对账

四级对账：订单、资金、份额、净值。默认工程容忍度：现金 0.01 元、份额 0.0001、净值 1e-8；实际平台可配置。出现 blocking 差异时暂停新订单。

来源优先顺序建议：官方/销售平台 API > 官方确认单/流水导出 > 手工导入 > 截图 OCR。OCR 只能作为候选数据，必须人工确认后进入正式账本。

月结存在未确认 QDII 时，先发布 `PROVISIONAL revision=1`，后续净值确认后补记 `revision=2...`，不覆盖历史月报。

## 10. SimulationBroker

模拟盘遵守场外交易的关键约束：截止时间、开放状态、限购、持有批次、费率、确认延迟、在途资金，以及 QDII 延迟、巨额赎回和暂停申赎场景。**不使用未来净值成交**。只有确认净值在决策之后真实到达或由测试场景注入时，才生成 `TradeFill`。

## 11. 飞书交互

买入使用红色主题 + `🔴 买入` 文本标签，卖出使用绿色主题 + `🟢 卖出`；同时保留文字，避免只依赖颜色。

自然语言支持“金额加1000”“卖一半”“为什么”“现在就交易”等。会话绑定 `session_id + order_id + version`。修改生成新版本，旧卡失效。自然语言永远不能直接完成真实交易；V1.2 的“现在就交易”含义是：重新拉状态 → 数据质量 → 重新风控 → 最终模拟确认卡 → 按钮确认。

权限：readonly / editor / confirmer / admin。生产环境必须启用飞书事件验签、防重放、身份映射和回调幂等。

## 12. 监控与验收

关键 SLI：任务成功率、数据新鲜度、AI Schema 通过率、飞书投递成功率、订单积压、对账差异率、重复回调幂等率。

进入下一阶段前至少满足：

- AI Schema 校验通过率 100%；不合格输出直接拒绝。
- 重复回调/重复提交不得产生重复订单或重复账务。
- 旧版本卡片 100% 拒绝。
- RED 数据质量 100% 阻断新单。
- blocking 对账差异 100% 阻断新单。
- 模拟盘覆盖普通基金、QDII 延迟、提前截止、节假日、限购、暂停申购/赎回、短持有惩罚费、部分确认/巨额赎回。
- 连续前瞻运行至少 4–6 周，并完整经历一次月结补记。

## 13. 开发顺序

1. 数据库 Schema + 订单状态机 + 审计。
2. Python 账本、费用、批次、对账、DataQuality。
3. SimulationBroker 前瞻仿真。
4. 飞书消息、会话、权限、旧卡失效。
5. Model Gateway + AI Schema + DeepSeek/Kimi/Qwen 分工。
6. 调度、监控、异常演练与 4–6 周模拟运行。
7. 真实资金接口继续后置，不在 V1.2 范围。
