# V1.3 Real Fund Data Connectors

Phase 8 connects the simulation system to explicitly registered, auditable fund-data endpoints. It does **not** add an open web scraper and it does not relax the confirmed-NAV settlement boundary.

## Trust boundary

A connector is bound to an existing enabled `DataSource`. The `DataSource.priority` and SLA remain the authority model used by DataQuality. A connector stores only an endpoint and the **name** of an optional secret environment variable; secret values are never persisted.

Default network policy:

```text
HTTPS only
no embedded URL credentials
no localhost / private / loopback / link-local / reserved targets
DNS must resolve only to public addresses
redirect targets are revalidated
JSON Content-Type only
bounded redirects / response bytes / fund count / timeout
```

Production deployments should still enforce network egress policy at the container/VPC layer; application DNS checks cannot mathematically eliminate DNS rebinding.

## STANDARD_JSON_V1

The endpoint returns:

```json
{
  "observed_at": "2026-09-13T10:00:00Z",
  "funds": [
    {
      "code": "000001",
      "name": "Example Fund C",
      "share_class": "C",
      "profile": {
        "category": "EQUITY",
        "risk_level": 4,
        "currency": "CNY",
        "sales_platform": "official",
        "trading_calendar": "CN"
      },
      "rules": {
        "subscription_open": true,
        "redemption_open": true,
        "purchase_limit": "50000",
        "fee_version": "2026-09",
        "fee_version_changed_unresolved": false,
        "announcement_fetch_ok": true,
        "missing_critical_fields": []
      },
      "nav": {
        "nav_date": "2026-09-13",
        "value": "1.2345",
        "status": "CONFIRMED",
        "observed_at": "2026-09-13T12:00:00Z"
      },
      "metadata": {
        "manager": "Example Manager"
      }
    }
  ]
}
```

`PENDING`, `ESTIMATED` and `PROVISIONAL` NAV values are retained as quality observations only. They never create `NavConfirm` and can never settle a simulated order. `CONFIRMED` NAV is rejected when its valuation date is in the future relative to the source observation in the configured business timezone.

If confirmed NAV sources conflict, a `DataQuality` RED `nav_conflict` record is created. A lower-authority source cannot overwrite a higher-authority confirmed NAV. Conflict data therefore remains visible instead of silently replacing settlement truth.

Fund trading rules are routed through the existing `FundDataIngestionService`, so source priority, SLA, fee-version uncertainty and critical-field conflicts use exactly the same DataQuality semantics as manual ingestion.

## Audit persistence

Phase 8 adds:

- `FundDataConnector`: registered endpoint, DataSource binding, ETag/Last-Modified and last sync status.
- `FundDataSyncRun`: one durable fetch/run journal with fetched/ingested/rejected counts.
- `FundDataObservation`: payload hash, normalized fund code, source, acceptance state and rejection reason.

The observation payload is retained for audit/replay. Repeating the same provider row is idempotent by `(connector_id, payload_hash)` and does not create a second business ingestion.

## API

All endpoints require internal authentication. Connector mutation and manual sync require system or ADMIN.

```text
POST  /fund-data/connectors
GET   /fund-data/connectors
PATCH /fund-data/connectors/{connector_id}
POST  /fund-data/connectors/{connector_id}/sync
GET   /fund-data/runs
GET   /fund-data/observations
```

## Scheduler

Default `Asia/Shanghai` fund-data sync windows:

```text
07:45 pre-market rules/profile refresh
13:20 pre-decision refresh
18:00 post-close first NAV refresh
22:15 pre-snapshot NAV refresh
23:15 late NAV refresh
23:30 formal portfolio snapshot retry
```

The existing 22:30 formal snapshot remains the primary daily snapshot. The 23:30 retry is idempotent and only succeeds when exact confirmed NAV is available for every held fund. QDII/FOF may still remain pending into a later business day; the system alerts and waits rather than substituting stale or estimated NAV.

## Secrets

For authenticated providers, register both `auth_header_name` and `auth_env_key`, for example:

```text
auth_header_name = Authorization
auth_env_key = FUND_PROVIDER_AUTHORIZATION
```

The connector never stores the value of `FUND_PROVIDER_AUTHORIZATION`. Missing environment secrets fail the sync and leave a durable failed run.
