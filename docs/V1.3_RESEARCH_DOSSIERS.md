# V1.3 Phase 4 — Multi-source Research Dossiers

## 目的

Phase 3 已能从多个显式注册的 RSS/Atom/JSON Feed 自动生成 Research Inbox，但如果同一基金在同一天收到多篇文章，直接逐篇进入 AI 会产生三个问题：

1. 同一基金一天可能得到多个相互竞争的 DecisionPlan / SUGGESTED 候选；
2. 相同内容被多个来源转载时会重复消耗 Kimi/Qwen/DeepSeek 配额；
3. CIO 的输入会被“文章数量”而不是“信息覆盖度”放大。

Phase 4 在采集和 AI 之间增加 `ResearchDossier`：**自动采集材料先按账户、基金、业务日合并成一个固定输入快照，再进入模型。**

```text
08:15 / 12:45 Collection
      -> raw collected documents + raw audit Inbox
13:00 ResearchDossierService
      -> one dossier / account / fund / business date
      -> one consolidated Research Inbox
13:15 ResearchPipeline
      -> Kimi -> Qwen -> DeepSeek
      -> at most one trade candidate per dossier
```

人工主动提交的 Research Inbox 不经过 Dossier，仍可按原 Phase 2 流程直接处理。

## 业务幂等边界

数据库唯一约束：

```text
(account_id, fund_id, business_date)
```

同一个模拟账户、同一基金、同一业务日最多一个自动 Dossier。Dossier 本身记录：

- `selected_document_ids`
- `suppressed_document_ids`
- `raw_research_item_ids`
- `source_names`
- `material_count`
- `source_count`
- `total_chars`
- `research_item_id`（最终 consolidated Inbox）
- 选材参数快照

Consolidated Inbox 的 idempotency key 由：

```text
account_id + fund_id + business_date + sorted(selected fingerprints)
```

确定，因此同一固定输入集合重试不会生成第二份 Inbox。

## 原始自动 Inbox 为什么仍保留

Collection 阶段仍会为每个抓到的 document 创建一条原始 Research Inbox。这些行是来源审计链的一部分，保存当时规范化后的 source/material payload；但它们不是独立的 AI 决策任务。

Dossier 成功后：

```text
raw document       -> DOSSIERED / SUPPRESSED
raw ResearchInbox  -> SUPERSEDED
consolidated Inbox -> NEW
```

`ResearchPipelineService.process()` 会查询 `ResearchCollectedDocument.research_item_id`。如果调用目标是原始自动采集 Inbox，直接抛 `ResearchProcessingConflict`，不会 claim、不会增加 attempt、不会调用模型。

`process_pending()` 在 SQL 查询阶段就排除所有被 collection document 引用的 raw Inbox。这样即使 13:00 Dossier 调度失败，13:15 也会 fail closed：**不研究，而不是逐篇研究。**

## 选材规则

默认：

```text
RESEARCH_DOSSIER_LOOKBACK_HOURS=72
RESEARCH_DOSSIER_MAX_MATERIALS=12
RESEARCH_DOSSIER_MAX_CHARS=80000
```

### 1. 时效过滤

只选择 `observed_at` 位于 lookback 内的自动文档。超过 lookback：

- document -> `STALE`
- raw Inbox -> `SUPERSEDED`
- reason -> `DOSSIER_STALE_MATERIAL`

不会为了凑材料把过旧新闻送给 CIO。

### 2. 内容级去重

Dossier 用 document 的 `content_sha256` 做跨来源去重。同一正文被多个 feed 转载时只保留最新一份，其余：

```text
status=SUPPRESSED
reason=DOSSIER_DUPLICATE_CONTENT
```

这与 Collection 的 `(source_id, fingerprint)` 去重不同：Collection 去重防同一个 feed 重复抓同一条；Dossier 去重防多个 feed 转载相同正文。

### 3. 来源多样性优先

去重后，先选择每个 collection source 最新的一条，再按时间顺序填剩余槽位。这避免单个高频 feed 用十篇相似文章挤掉其他来源。

### 4. 双预算

同时限制：

- material 数量；
- 正文总字符数。

超过预算的文档进入 `SUPPRESSED / DOSSIER_LIMIT_EXCEEDED`。`RESEARCH_DOSSIER_MAX_CHARS` 启动校验要求不超过全局 `AI_MAX_SOURCE_CHARS`。

## 当日新增材料

一旦某基金当日 Dossier 已创建，输入集合不再静默变化。随后自动采集到的新文档：

```text
document -> DEFERRED
raw Inbox -> DEFERRED
reason -> DOSSIER_ALREADY_EXISTS:<dossier_id>
```

只要仍在 lookback 内，后续业务日可以重新参与新的 Dossier。这保证当天 CIO DecisionPlan 对应的是一个固定、可复现的输入集合。

## API

所有接口都要求内部认证。

只读：

```text
GET /research/dossiers
GET /research/dossiers/{dossier_id}
```

查询支持 `account_id`、`fund_id`、`business_date` 和 `limit`。

手工装配：

```text
POST /research/dossiers/assemble
```

仅 system principal 或 ADMIN。它使用与 13:00 scheduler 完全相同的服务，不提供绕过预算/幂等规则的特殊路径。

## 调度顺序

默认 `Asia/Shanghai`：

```text
08:15 collection morning
08:45 morning brief
12:45 collection pre-decision
13:00 dossier assembly
13:15 AI research pipeline
13:30 early-cutoff risk
14:00 regular risk window
```

Dossier 用本地时区计算 `business_date`；数据库时间仍遵循项目约定保存 UTC 语义。

## 与 DataQuality 的关系

Dossier 只解决“研究材料怎么合并”，不会把基金质量变成 GREEN。

13:15 consolidated Inbox 进入 `ResearchPipelineService` 后仍先执行 `DataQualityGate`：

- RED -> BLOCKED / WAIT，不继续 Kimi/Qwen；
- GREEN/YELLOW -> 按现有规则继续；
- settlement eligibility 仍与 research quality 分离。

## 审计链

完整链路：

```text
ResearchCollectionSource
 -> ResearchCollectionRun
 -> ResearchCollectedDocument
 -> raw ResearchInbox
 -> ResearchDossier
 -> consolidated ResearchInbox
 -> ResearchEvidence
 -> DecisionPlan
 -> SUGGESTED Order
 -> OrderEvent / Risk snapshot
```

Dossier 创建写 `AuditLog(action=research.dossier.assemble)`，记录目标基金、账户、业务日、选中/抑制文档和 consolidated Inbox。

## 失败边界

- Dossier assembler 异常：raw Inbox 仍不能被 13:15 pipeline 处理。
- 没有可选材料：不生成空 Dossier。
- 当日已有 Dossier：新材料 DEFERRED，不覆盖历史输入。
- 同时装配出现唯一约束竞争：返回/记录 conflict，不创建第二个 Dossier。
- 模型失败：按 Phase 2 的持久化阶段恢复机制处理，与 Dossier 不耦合。

## 非目标

Phase 4 不实现：

- 自动全网搜索；
- 通用网页浏览器抓取；
- 模型自行决定新来源；
- 用 AI 给来源打一个不可解释的“真伪分”后直接过滤；
- 自动批准订单；
- 自动提交模拟订单；
- 实盘交易；
- 独立回测中心。
